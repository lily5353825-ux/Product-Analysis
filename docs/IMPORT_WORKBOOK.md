# 每日工作簿导入（v0.2）

当前页面直接读取工作簿，不要求先填写 CSV。选择 XLSX 后，解析和计算均在浏览器内存进行；不会上传订单或广告记录，刷新后需重新选择文件。演示按钮仅使用合成数据。

## 已确认的业务设置
- 按两类产品汇总：106 英寸组合沙发、79 英寸沙发床，各含颜色/左右向变体；单独脚凳不计入。
- 每类每天 2 个订单，合计每天 4 单。周期目标按筛选区间的自然日数计算，首次上线日期尚未精确提供，不虚构上线日。
- 每类目标各自按订单编号去重；合计目标进度用两类订单数之和（品类订单）。同单购买两类可分别贡献目标，去重总订单作为独立指标展示，不能用它与品类目标之和直接比较。
- 处于新品阶段，用户描述上线约一个月。GMV 目标暂未设置，广告预算暂未要求；不显示虚假的完成率或预算余额。
- 库存充足来自人工确认，不代表已同步实时库存，也不能推导库存可售天数。
- 归因窗口、报表时区、目标 ACOS 尚未确认。首版展示历史实际与数据诊断，不自动给出加减预算金额。

## 工作表与字段
1. SKU数据：按实际商品名称识别 106/79 英寸品类，以 SKU、Item ID 建立映射；以币种字段验证 USD。未知商品不能静默归类。
2. 订单：A=PO#，B=Order#，C=日期，E=状态，F=数量，G=SKU。源文件 H–K 的旧表头存在错位，用户确认 I=商品单价、J=折扣、K=运费。GMV 从 I×数量−J 重算，排除运费；不使用源 L 列“销售额”。当前数据数量均为 1、折扣为 0。多件订单且有折扣/运费时，导入器要求先明确每行或每件口径。
3. Item Data（允许末尾空格）：按 Date、Campaign Id、Ad Group Id、Item Id、SKU Id、Impressions、Clicks、Ad Spend、Orders、Total Attributed Sales、Advertised SKU Sales、Other SKU Sales 读取原始值；不读取前部带公式的销量、销售额、ACOS作为看板事实。

订单以 Order# + SKU 临时识别行，重复时拒绝；当前源没有正式订单行 ID，未来同 SKU 多行或拆单需升级数据契约。取消订单不计有效订单/GMV。源没有退款明细，首版不声称已计算净收入。

## 广告粒度修订
初版 CSV 草案限制一个 campaign 只有一个 SKU。实际工作簿提供商品粒度数据，因此本版按 日期 + campaign + adgroup + item 唯一键保存，再按品类聚合；共享 campaign 不需要重复复制花费。

同商品同日的订单销售额可能被原工作簿公式重复带到多个广告行。看板必须从订单表独立去重计算销售事实，不能累加广告表前部的销售额列。

主广告 ACOS/ROAS 使用 Advertised SKU Sales（直接商品归因销售），总归因销售和其他 SKU 归因销售保留区分。报表日期归属未确认，因此广告销售占商品 GMV 仅供参考，不能用二者之差推断自然销售。

## 日期与缺失数据
默认使用订单与广告记录日期区间的重叠部分，避免把较晚销售日与缺失广告日混比。区间只表示文件中存在记录，不证明全日/全周期已完整导出。页面提示数据覆盖和归因限制；数据缺失不可伪装为确认零交易。日期在日期层面筛选，不随电脑时区移动。

当前导入数据契约定义在 src/web/importer.js；config/data-contract.json 和 data/templates 是后续标准 CSV 接入草案，尚未接入页面。业务汇总算法位于 src/web/dashboard-metrics.js；旧 src/domain/metrics.mjs 继续保留基础公式测试。
