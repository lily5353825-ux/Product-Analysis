# MVP：两款 Walmart 新品沙发

## 范围与业务假设
单店铺、同币种、两款沙发；先用导出的 CSV，按日分析。SKU_A、SKU_B 仅为占位。业务日期使用报表配置时区，不能默认用浏览者电脑时区。所有目标与预算由业务输入，不推定售价、销量、毛利或广告归因窗口。

## 页面模块
| 顺序 | 模块 | 内容与交互 |
|---|---|---|
| 1 | 顶部筛选与数据状态 | 日期区间、两款合计/单款、币种、更新时间、数据覆盖截止日、广告成熟截止日；默认截至昨日 |
| 2 | 目标进度 | GMV、去重订单、广告花费、预算消耗、TACOS、广告销售占比；每张卡展示实际、目标/上限、差额和状态 |
| 3 | 两款对比 | 每款一行：GMV、订单、件数、客单价、花费、ACOS、ROAS、预算余额、库存可售天数；总订单另行去重 |
| 4 | 每日走势 | GMV 实际与目标同图；花费与预算同图；选中日期可查看明细，不使用不同单位的同一纵轴 |
| 5 | 广告诊断 | campaign 维度展示曝光、点击、CTR、CPC、归因订单、CVR、ACOS、日预算使用率 |
| 6 | 操作建议 | 加预算/降预算/调广告/继续观察；展示触发数据、规则、建议幅度、证据区间、禁用原因；人工记录执行 |
| 7 | 数据与目标设置 | CSV 导入预览、错误行提示、字段映射、重复批次提示、每日计划编辑、配置未完成提示 |

空数据、未设置目标、零销售、预算为零、归因未成熟、刷新失败都要有独立状态；不能显示为成功达标。

## 目标与实际差距
目标必须按“日期 × SKU”保存：gmv_target_cents、orders_target、ad_budget_cents。
- 周期目标 = 所选周期内每日目标之和。
- 截至日期目标 = 周期开始至数据覆盖截止日的目标之和。以它比较当前实际，避免月初和整月目标比较。
- 有利差额（GMV/订单）= 实际 − 截至日期目标；缺口 = max(目标 − 实际, 0)。
- 完成率 = 实际 / 同期目标；目标为 0 时显示 N/A。
- 广告花费显示“余额 = 周期预算 − 实际花费”，负数明确标为超支；花得多不使用绿色达标。
- 花费节奏 = 实际累计花费 / 截至日期计划预算；>110% 为超前，<90% 为偏慢。
- ACOS/TACOS 是上限指标，差距使用百分点，例如 32% 对 25%：高于上限 7 个百分点。
- 合计比率从合计分子/分母计算；两个 SKU 的百分比不能取算术平均。
- 两款订单目标之和标为“SKU 订单目标”，不作为店铺去重订单目标。MVP 合计去重订单只展示实际；跨 SKU 同单不重复计算。
- GMV/订单进度：低于同期目标 90% 为落后，90%–100% 为接近目标，≥100% 为达标；颜色附文字。阈值可配置。
- 可选期末预测：最近 7 个完整销售日的日均 × 剩余天数 + 已实现值；标注粗略预测，不能作为单独加预算依据。

## 实现顺序与验收
1. **首个步骤：冻结数据契约与计算口径（本次完成基础）**。交付模板、配置、纯计算函数与测试；用同单跨 SKU、退款、取消、零分母场景核对结果。真实业务目标和字段映射仍待填写。
2. **导入与单页闭环**。先接 products、order_lines、daily_plan；实现数据校验与顶部筛选、GMV/订单/目标差距，加入两款对比与每日走势。验收：同一 CSV 重复导入不翻倍，跨 SKU 同单合计只计一次。
3. **广告与建议**。接 campaigns、ad_daily、inventory_daily；先实现口径/成熟度校验，再实现规则，展示触发证据与操作日志。验收：未配置目标、缺数据、冷却期、库存不足时禁止加预算；共享 campaign 拒绝导入。
4. **上线与交接**。验证响应式与空状态、说明导入步骤和数据存储方式；以合成数据发布预览，按 DEPLOYMENT.md 决定真实经营数据的存储方式。
5. **后续迭代**。自动 API 同步、账户鉴权、团队协作、共享 campaign 分摊、多店铺、退货财务核算。均不属于本次 MVP 基础配置。

首个页面完成标准：两款真实数据可导入，指标可追溯到明细，同期目标差距正确，不依赖手工重新计算。
