# 部署与运行

## 当前
仓库只有实施基础和可运行的指标测试，没有网页构建/启动命令，没有已部署链接。运行 node --test（或安装 npm 后运行 npm test） 验证指标。无需环境变量、数据库或 Walmart 密钥。

## 首版页面建议
沿用本仓库的 JavaScript ES modules 计算层，采用 Vite + React 实现 UI。届时安装并锁定经过验证的依赖版本，增加 dev/build/preview 脚本与 package-lock.json；禁止在文档中提前声称这些命令当前可用。

首版以浏览器上传 CSV 为入口，数据只保存在当前浏览器内存；刷新清空。若增加本地持久化，明确设备可见范围、清除按钮和过期策略。目标与导入设置在 UI 中填写，不要求将真实数据提交到公开仓库。

## 页面完成后的发布步骤
1. 运行指标、导入和规则测试及生产构建；用合成数据验收筛选、空状态、超支和归因延迟。
2. 选择静态托管。若使用 GitHub Pages，配置项目子路径 /Product-Analysis/ 并验证资源路径；工作流仅发布构建文件和合成演示数据。
3. 手工验证移动端、中文、币种、页面刷新、CSV 错误提示。
4. 发布说明中列出存储方式、更新日期、已知口径限制和回滚版本。

如需要团队共享真实数据或 API 自动同步，先增加身份认证、服务端数据存储和权限控制；访问密钥只放服务端密钥管理，不能嵌入前端或提交 Git。
